# 第 1 章：定义目标与边界

## 目标
定义第一版的最小成功标准与边界，不做提前设计。

JsBridge 是 JS 与 Native 之间的"协议化通信层"：把调用、响应、错误用统一格式传递，不承载业务本身。

## 最小成功标准（MVP）
1. JS 可以调用 Native。
2. Native 可以把结果回给 JS。
3. 双方能区分成功与失败。

## 非目标（刻意不做）
1. 复杂权限系统（按用户角色的细粒度策略）。
2. 完整插件生态（安装、卸载、版本治理）。
3. 跨端共享同一套运行时代码——四端只共享协议。

## 与本仓库的对应
- MVP 与非目标最终演化为 `docs/03-protocol.md`（协议边界）与 `AGENTS.md` 的两条核心原则：Protocol consistency（四端协议一致，运行时各自实现）与 Progressive enhancement（除核心协议外一切可插拔）。
- 最小演示场景：`ping -> pong`；本仓库示例工程的对应场景是 `getUser` 请求-响应与 `timerLog` 流式回调。
- 参考实现在 `js_bridge_android/js-bridge-core`，iOS/Flutter/HarmonyOS 严格对齐同一协议。

## 产出物
1. MVP 目标 + 非目标清单。
2. 验收标准：调用成功、失败、超时如何判定。

## 验收清单
- Demo 页面点击按钮可触发 Native 调用并拿到回调结果。
- 每个新增需求都能映射到 3 个 MVP 目标之一；无法映射的归入非目标或后续章节。
